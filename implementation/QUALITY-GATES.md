# Acceptance criteria and QA matrix

## Site-level acceptance
| Area | Verification |
|---|---|
| Narrative | Above-the-fold text states AI+digital engineering, control, and multidisciplinary scope |
| Curriculum | 12 chapters in 4 parts, correct ordered links and unique learning outcomes |
| Workflow | Planning, exploration, progressive specs, bounded agents and delivery visibly connected |
| Multi-discipline | Substantive electronics/mechanical/software interaction plus physical lead-time |
| True AI | At least one authentic, source-stamped agent trace/diff/check/reviewer artifact |
| Model honesty | V0 expected FAIL and CI PASS separated; experimental physical inputs labeled synthetic |
| Preservation | All old direct links work and v1 behavior can be recovered |
| Engineering | `npm run check` + `npm run evidence` executed and results recorded, not assumed |
| Accessibility | Keyboard, focus, labels, zoom/mobile, text outputs and reduced-motion reviewed |
| Cross-chapter | No two chapters use same primary learning experience; conclusions lead onward |
| Sources | Identifiable revision, inputs, method and known limitations for reported results |

## Editorial review per chapter
- Meaningful engineering problem visible immediately.
- New knowledge/decision added beyond prior chapter.
- Clarity and concision; define jargon once, avoid repeated defensive caveats.
- Primary diagram or interaction is informative and accessible.
- Explicitly identify simulated versus actual work.
- Distinguish software release cadence from physical product readiness where relevant.
- Honest human vs agent decision authority.

## Regression test checklist
- `npm run check`
- `npm run evidence`
- Existing V0 model/source/coverage tests
- Source-ID resolution and proposal validation
- Home/Learn chapter registry and navigation
- Old and new routes including direct reload and GitHub Pages base path
- Interactive input invalid/reset/keyboard behavior
- Actual browser desktop/mobile screenshots
- Published GitHub Pages smoke test after authorized release

## Gate semantics
BLOCKED = feature missing or untested, NOT 'passes by documentation.'
OWNER ACCEPTANCE = explicit editorial/engineering approval; never generated by an agent.
